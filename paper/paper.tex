\begin{abstract}
The AKBC 2026 shared task asks a language model to recover the complete set of
objects for a given subject--relation pair without retrieval, external
knowledge bases, or additional training. We describe \systemname, a
relation-specific probing system that runs an open-weight language model
locally. Each query receives a short identity description followed by multiple
rationale-bearing generations with rotating training examples. Relation-wise
aggregation uses numeric medians, generation-first empty-answer voting, and
low-threshold set union. A targeted completion step is retained for borders
and awards, while verification is restricted to the already strong border
workflow. Deterministic parsing and train-derived alias normalization convert
the generations into submission-format JSONL. Thresholds are calibrated only
on complete training traces. This draft specifies the method and experimental
protocol; quantitative results for the new system will be added after the
replacement model is evaluated.
\end{abstract}

\section{Introduction}
\label{sec:introduction}

How can knowledge stored in a language model be turned into a complete database
entry? A model may readily answer that the Dominican Republic borders Haiti,
yet the same question becomes considerably harder when the expected answer
contains nine neighboring countries, 80 award recipients, or no object at all.
The AKBC 2026 shared task isolates this problem: given a subject \(s\) and a
relation \(r\), a system must predict the complete set of object strings
\(\{o_1,\ldots,o_k\}\) \citep{akbc2026}.

Consider a country with three gold-standard neighbors. Returning two correct
neighbors yields perfect precision but only \(2/3\) recall; adding three
plausible but incorrect neighbors restores no recall and reduces precision to
\(2/5\). Empty sets introduce the opposite problem, since inventing a single
death city for a living person changes an otherwise perfect row into a complete
miss. The central design question is therefore not merely whether the model
knows a fact, but when another candidate should be admitted to the predicted
set.

We address this question with description-first relation-wise
self-consistency. The system first identifies the exact subject, then generates
independent candidate sets through prompts that expose different recall paths,
such as scale checks, clockwise border enumeration, or chronological award
enumeration. Empty answers participate directly in aggregation instead of
blocking generation through a preliminary gate. The main takeaway is simple:
relations with different cardinalities and failure modes should share one
orchestration pattern but use different aggregation rules.

The setting is closed-book: inference may use one or more open-weight neural
models with at most 32 billion total published parameters, but it may not query
the web, a retrieval index, an external corpus, or a knowledge base. The rules
also prohibit fine-tuning and continued pretraining. In-context examples,
multi-step inference, and non-neural post-processing are allowed
\citep{akbc2026}. Our system consequently uses the training split only for
few-shot demonstrations and uses no external factual source.

\section{System}
\label{sec:system}

\subsection{Common inference procedure}

All calls use one locally hosted open-weight model through an OpenAI-compatible
LM Studio endpoint. For every subject--relation pair, the model first produces
a short identity anchor describing entity type, scope, and likely namesake
confusions. The same model then receives this anchor as explicitly uncertain
context and generates $n_r$ concise rationales and candidate sets. Each pass
uses a different seed, recall focus, and rotating leave-one-subject-out sample
of training demonstrations. For relations that permit empty answers, example
selection alternates between empty and non-empty rows.

Candidate strings are parsed from the first valid JSON structure and
normalized with the official evaluator's punctuation, apostrophe, case, and
diacritic rules. We additionally construct relation-specific alias maps from
the nested aliases in the training split. An alias is rewritten only if all of
its training occurrences identify the same canonical entity. Alias
canonicalization happens before support is counted, so equivalent surfaces
reinforce rather than split a vote. Raw responses, parsed values, rationales,
seeds, token counts, and aggregation decisions are retained in immutable
per-row traces.

We compare two output-control modes while holding model weights, prompts, and
decoding settings fixed. The first requests JSON in natural-language
instructions and applies a tolerant parser. The second converts Pydantic response
classes into JSON Schema and asks LM Studio to constrain generation with the
corresponding grammar. Schema constraints guarantee structure rather than factual
correctness; if a constrained generation is interrupted or fails validation, the
same tolerant parser is used as a recorded fallback. For awards, the schema
separates recipient, work, and year before aggregation.

\subsection{Numeric relations}

For area and capacity, respectively 20 and 15 prompts request independent
estimates. The area
prompts distinguish total surface area from land-only area and explicitly
request square kilometres. The capacity prompts distinguish maximum attendance
from a smaller seated configuration. Consider estimates of 35,000, 35,100, and
50,000 spectators: the system returns the median, 35,100, rather than allowing
one recalled concert configuration to determine the prediction.

\subsection{Death locations}

Twenty passes independently recall the most specific death locality or return
an empty candidate set. Empty is treated as a first-class candidate and wins
only when it has a strict plurality and reaches a threshold calibrated from
complete training traces. Otherwise the highest-support locality is retained,
with at most one city in the final output. This generation-first rule avoids
discarding a recoverable city because a separate status classifier was
uncertain.

\subsection{Stock exchanges}

Ten passes separately recall primary listings, secondary or dual listings, and
the legal entity attached to each exchange. Candidate exchanges survive when
their pass-level support reaches a train-calibrated threshold. Empty may still
win by strict plurality at a separate train-calibrated threshold. Prompts ask
for exchange names rather than ticker symbols and explicitly distinguish a
subsidiary from its listed parent.

\subsection{Land borders}

Border candidates are generated in three ways: clockwise enumeration,
independent geographic recall, and a focused check for enclaves, exclaves, short
borders, and integral overseas territories. A separate completion prompt sees
the merged set and returns only omitted candidates. The verifier then removes
maritime neighbors and borders that arise solely through non-integral

\subsection{Award recipients}

A single output may contain 610 recipients, for which one undifferentiated
prompt is prone to both truncation and omission. We therefore partition recall
into five time windows---before 1960, 1960--1979, 1980--1999, 2000--2014, and
2015--1 July 2026---and add a sixth pass organized by profession, nationality,
and recipient type. Twenty seeded passes cycle through these foci. A recipient
is retained when it occurs in at least 5\% of passes, which reduces to a
high-recall union at $n=20$. One completion pass searches for missing editions
and recipient types. We apply no binary award verifier because preliminary
experiments showed that it removed many correct long-tail recipients.

\paragraph{Model and threshold selection.}
We first compare models on a fixed 12-row stratified smoke set containing two
examples per relation. All support and empty-answer thresholds are selected
from complete leave-one-out training traces with the official evaluator. The
locked configuration is then evaluated once on all 478 validation rows. We do
not tune thresholds or entity-specific rules against validation answers.

\paragraph{Baselines and ablations.}
The primary historical baseline is the completed GPT-OSS-20B prototype. The
new system removes its hard empty-answer gates, numeric selector, generic
verifier, and award verifier. Controlled comparisons vary the eligible model
and replace prompted JSON with schema-constrained output while keeping the
pipeline fixed. Additional ablations vary self-consistency sample count and the
optional train-derived SyntheticCoT demonstrations.

\section{Conclusion}
\label{sec:conclusion}

We presented a single description-first self-consistency pipeline for
closed-book knowledge base construction. It shares one orchestration pattern
across relations while assigning numeric, empty-aware, union, and threshold
aggregation according to relation cardinality. Train-only calibration and
alias maps keep non-neural decisions within the challenge's evidence boundary.
The remaining empirical question is whether a more knowledgeable eligible
model supplies enough correct numeric and identity-level candidates to exceed
the strong validation reference.

\section*{Limitations}

The system cannot recover facts absent from the selected model's pretraining
data, which is particularly relevant for deaths, listings, and award recipients
close to the July 2026 reference date. Reusing the same model for border
generation and verification may reinforce rather than correct a misconception.
Self-consistency stabilizes recalled candidates but cannot recover a fact that
never appears in any sample, while award enumeration can remain incomplete
after temporal partitioning. Train-calibrated thresholds may also shift under
distribution change. We therefore preserve the test data for one final
evaluation and record every prompt, response, configuration, and row shard.
